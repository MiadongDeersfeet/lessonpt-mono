# LessonPT · Studio Ledger 디자인 시스템

2026-11-02 / feature/mobile-teacher-ux / 로컬 구현, 미배포

## 제품 방향

음악 교사가 학생의 변화와 수업 기록을 빠르게 확인하는 업무 공간이다. 음악성을 장식으로 과장하기보다 차분한 스튜디오의 정돈된 기록 도구로 해석했다. 기본 색상은 밝은 회백색, 진한 잉크색, 주요 동작에 제한적으로 쓰는 청록색이다. 브랜드 심벌은 반복되는 박자와 기록의 선을 나타낸다. 로그인 소개 영역의 악보 모티프는 코드 기반 벡터/레이아웃이며 정보 화면에는 장식을 반복하지 않는다.

## 선별한 원칙과 적용

- Jakob Nielsen의 상태 가시성: 현재 메뉴, 선택된 학습 탭, 조회/저장 중 상태, 오류와 비어 있는 상태를 명확히 구분한다. https://www.nngroup.com/articles/ten-usability-heuristics/
- Nielsen의 일관성과 기억보다 인지: 학생·출강처·커리큘럼의 메뉴를 모바일에서도 항상 표시한다. 같은 버튼 위계, 같은 라벨/입력 규칙, 같은 모달 구조를 사용한다. 아이콘에는 텍스트/접근성 이름을 함께 둔다.
- Nielsen의 오류 예방·사용자 제어: 파괴적 동작은 주요 동작과 색/강도를 구분하고, 기존 확인창과 학생 폼의 미저장 입력 보호를 유지한다.
- Dieter Rams의 유용성과 절제: 실제 데이터와 작업에 시각적 우선순위를 부여한다. 검증하지 않은 통계, 실시간 상태, 장식용 차트를 제품 화면에 추가하지 않는다. https://www.vitsoe.com/us/about/good-design
- 근접성·유사성에 따른 정보 그룹화: 이름과 아바타, 라벨과 값, 관련 작업을 그룹으로 묶고, 반복되는 페이지 제목/설명/추가 동작을 같은 위치에 둔다. 이는 이 프로젝트의 설계 판단이며 실사용 연구 결과로 주장하지 않는다.
- WCAG를 실무 기준으로 참조: 색상 외 상태 텍스트, 가시적 포커스, 입력 라벨, 명시적 비밀번호 표시 기능, 주 동작의 44px 높이를 적용한다. 전체 WCAG 준수 인증은 아니다. https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum

## 토큰

- 배경 #f6f7f5, 표면 #ffffff, 주요 텍스트 #192d32, 보조 텍스트 #586b70.
- 주요 동작 #176b61, hover #105349, 선택 영역 #e7f2ed. 삭제 #a33d3d. 상태 색상은 텍스트와 함께 사용.
- 자체 제공 Noto Sans KR Variable 100–900. 외부 폰트 CDN 요청 없음. font-display:swap 및 unicode-range에 따른 부분 파일 요청. 라이선스는 public/fonts/Noto-Sans-KR-LICENSE.txt에 포함.
- 본문 14px, 주요 제목 28–32px, 데이터 표 13px, 보조 정보/라벨 11–13px. 숫자는 tabular-nums. 입력은 모바일에서 16px.
- 컨트롤 높이 44px, 입력/버튼 반경 9px, 패널 반경 16px. 간격은 8/16/24/32px 중심으로 운용.
- 주요 텍스트/흰색 14.36:1, 보조 텍스트/흰색 5.60:1, 주요 버튼/흰색 6.34:1, 선택 텍스트/선택 배경 5.53:1, 삭제 텍스트/흰색 6.38:1. 입력 테두리 #81958b/흰색 3.18:1. 이 수치는 토큰 쌍의 계산값이며 모든 렌더링 상태의 자동 검사값은 아니다.

## 화면 구성

- 로그인/가입: 데스크톱은 브랜드 소개와 입력 영역을 분리. 모바일은 소개 영역을 생략하고 즉시 계정 입력. 비밀번호 표시/숨김은 제출하지 않는 독립 동작.
- 공통 레이아웃: 데스크톱은 고정 폭 사이드바와 경로/계정 헤더. 900px 이하는 하단 3개 내비게이션, safe-area 및 본문 하단 여유 확보.
- 학생: 데스크톱은 비교가 쉬운 표, 모바일/태블릿은 이름·연락처·출강처·커리큘럼·진도·작업을 그룹화한 카드. 검색과 목록 인원 안내. 기존 이메일·Portal 숨김 정책 유지.
- 출강처/커리큘럼: 동일한 제목/설명/추가 버튼과 목록 디자인. 작은 화면은 항목별 카드와 분리된 작업 영역.
- 학생 상세: 기본정보/학습관리 탭, 출강처와 커리큘럼 계층, 진행 배지와 게이지, 학습 상태를 동일 토큰으로 정리.
- 커리큘럼 구성/자료/과제: 공유된 표·카드·폼·버튼·자료 컨트롤과 오버레이를 적용. 자료가 없는 빈 모바일 라벨은 숨긴다. 기록/과제/자료 API는 유지한다.
- 입력창: 학생·출강처·이름 폼은 공통 Overlay 사용. 작은 화면은 하단 시트, 긴 편집기는 스크롤 가능한 본문. 기존 삭제/배정 창도 동일 색상·간격·버튼 체계로 표현한다.
- 피드백: 비어 있는 목록은 문서 모티프와 안내, 오류는 별도 오류 표면, 로딩은 상태 문구와 표시기. reduced-motion 설정 지원.

## 코드 구조

- styles.css는 진입점만 유지. styles/tokens.css, workspace.css, auth.css, responsive.css로 역할 분리. 이전의 누적된 기본/테마 재정의 제거.
- 공통 Brand, Icon, AuthLayout을 추가. AppLayout에서 동일 메뉴와 브랜드를 사용한다.
- @fontsource-variable/noto-sans-kr 5.3.1을 정확한 버전으로 추가. npm production 의존성 감사 취약점 0. 전체 개발 도구 의존성 경고는 별도 기존 유지보수 범위.
- 로그인/가입/학생/출강처/커리큘럼 페이지와 공통 폼/피드백을 수정. 이번 디자인 작업에서 인증/DB/API 계약이나 서버 배포 설정을 추가로 변경하지 않았다. 이전 학생 기능 잠정 중단 구현은 유지한다.

## 검증 결과

- 전체 프론트엔드 25파일 / 150개 테스트 통과. 초기 과도한 병렬 작업자 실행은 시간 초과했으며 maxWorkers=2로 재실행해 전부 통과했다. 테스트 제한 시간을 늘려 실패를 감추지 않았다.
- TypeScript 검사, Vite production 빌드, diff 공백 검사 통과. lint 오류 없음, 기존 effect/context 관련 경고 10개 유지.
- 초기 JS 304.27KB / gzip 93.51KB, 코드 분할 유지. CSS 115.47KB / gzip 34.81KB(폰트 unicode-range 정의 포함). 폰트 파일 전체 약 3.51MB가 빌드에 포함되지만 브라우저는 필요한 문자 범위만 요청한다. 실제 초기 글꼴 전송량/실사용 성능을 측정한 것은 아니다.
- 로컬 가상 API로 9개 화면 × 6개 크기: 320×568, 375×667, 390×844, 430×932, 768×1024, 1440×900. 학생·출강처·커리큘럼 목록, 커리큘럼 구성, 학생 기본정보/학습관리, 로그인, 가입, 학생 중단 안내. 모든 표본에서 문서 scrollWidth가 clientWidth를 초과하지 않음.
- 학생 추가 시트 320px, 저장 거절 시 입력 유지/오류 안내, 미저장 닫기, 학습 탭 직행을 확인. 대표 화면은 채팅 작업 폴더의 outputs/lessonpt-redesign에 저장.
- 실제 기기 키보드/노치, 스크린리더, 200% 확대 전수, Lighthouse, 실제 운영 저장/삭제/업로드는 미검증. 운영 DB를 수정하지 않고 합성 데이터만 사용했다.

## 적용 상태

로컬 브랜치 feature/mobile-teacher-ux의 미커밋 변경이다. 커밋/푸시/배포하지 않았다. Render와 OCI 운영 화면에는 아직 적용되지 않았다. 제품 품질을 목표로 구현했지만 실제 사용자/실기기 검증을 마친 출시 인증으로 표현하지 않는다.
